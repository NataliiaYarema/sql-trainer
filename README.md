**[Відкрити тренажер →](https://sql-trainer-zeta.vercel.app/)**

![Екран тренажера](public/og-cover.png)

## Що це

Веб-тренажер для практики SQL: 125 завдань, розкладених по 8 рівнях, з бізнес-контекстом, трьома підказками та поясненням після кожної відповіді.

Запити виконуються по-справжньому — прямо в браузері працює **PostgreSQL** (через [PGlite](https://pglite.dev), скомпільований у WebAssembly). Не емуляція й не спрощений діалект: це той самий Postgres, який ви зустрінете на роботі, з `DATE_TRUNC`, `EXTRACT`, віконними функціями та його ж повідомленнями про помилки.

Ваш запит перевіряється за даними, які він повернув, а не за текстом, тому будь-який коректний варіант розв'язку буде зарахований.

Сервер не потрібен: база живе у вкладці браузера й піднімається заново при кожному завантаженні сторінки. Змінити дані вона не дозволить — з'єднання відкрите в режимі `read-only`, тож жоден `INSERT` чи `DROP` не зіпсує завдання наступному.

## Як почати

Відкрийте [тренажер](https://sql-trainer-zeta.vercel.app/) і виберіть рівень — усі вісім доступні
одразу, реєстрація не потрібна. Перший запит на сторінці відпрацьовує довше за наступні: браузер
завантажує PostgreSQL і створює таблиці.

Прогрес зберігається у вашому браузері, тож можна закрити вкладку й повернутися пізніше. Він
локальний: на іншому пристрої почнеться з нуля.

## Рівні

| Рівень | Тема                   | Про що                                                                                      |
| ------ | ---------------------- | ------------------------------------------------------------------------------------------- |
| 1      | Основи вибірки         | `SELECT`, `FROM`, `WHERE`, `ORDER BY`, `LIMIT`, `DISTINCT`                                  |
| 2      | Групування й агрегація | `GROUP BY`, `HAVING`, `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`                                   |
| 3      | Об'єднання таблиць     | `JOIN`, `INNER JOIN`, `LEFT JOIN`, `ON`, `USING`                                            |
| 4      | Підзапити й CTE        | `WITH`, `AS`, `IN`, `NOT IN`, `NOT EXISTS`                                                  |
| 5      | Віконні функції        | `OVER`, `PARTITION BY`, `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `LAG`, `LEAD`, `NTILE`          |
| 6      | Дати та рядки          | `DATE_TRUNC`, `EXTRACT`, `INTERVAL`, `AGE`, `TO_CHAR`, `TRIM`, `INITCAP`, `SPLIT_PART`      |
| 7      | Умови й множини        | `CASE`, `WHEN`, `THEN`, `ELSE`, `END`, `COALESCE`, `NULLIF`, `UNION`, `INTERSECT`, `EXCEPT` |
| 8      | Аналітичні кейси       | `WITH`, `DATE_TRUNC`, `COUNT`, `DISTINCT`, `FILTER`, `LAG`, `NTILE`                         |

Кожен рівень супроводжує сторінка теорії з тими самими конструкціями: короткий підсумок,
кілька прикладів SQL на реальних даних і типові пастки. Тем стільки ж, скільки рівнів, — вісім.

Усередині кожного рівня складність зростає за однаковою схемою: **8 базових завдань → 5 середніх → 2 комплексних**, окрім рівня 3, де завдань більше й пропорція інша — **10 → 7 → 3**. Тип показано позначкою на картці завдання, а точний склад кожного рівня закріплений у `LEVEL_PLAN` (`src/tasks/index.js`) і звіряється тестом — випадково порушити його не вийде.

Комплексне завдання наприкінці рівня зводить разом усе, що було до нього. Наприклад, на рівні 2 це «категорії, де середня ціна понад 100 і водночас більше 5 товарів», а на рівні 5 — накопичена сума витрат клієнта від замовлення до замовлення разом із сумою попереднього (`SUM(...) OVER (PARTITION BY customer_id)` і `LAG`).

На рівні 8 чотири завдання («Аналіз конверсії користувачів») утворюють наскрізний кейс: кожне
наступне будується на висновку з попереднього, а картка завдання показує бейдж
«Кейс: Аналіз конверсії користувачів — крок N з 4».

## Як це працює

Тренажер починається з екрана вибору рівня — усі вісім відкриті одразу, тож можна почати з того, що вам потрібно, а не пробиватися крізь `SELECT *` до віконних функцій. Обраний рівень показує лише свої завдання (15 на більшості рівнів, 20 на рівні 3); повернутися до списку можна будь-коли кнопкою в шапці.

Усередині рівня рух вільний в обидва боки: смужка з номерами завдань над карткою показує статус кожного (нове, розв'язане, підглянуте) і дозволяє перейти на будь-яке, а не лише вперед по черзі.

Прогрес зберігається в `localStorage` браузера. Балів, серій і відзнак немає: картка рівня показує відсоток пройденого, а подробиці — дашборд. Написаний, але ще не перевірений SQL теж зберігається окремо для кожного завдання, тож повернення до завдання (навіть після перезавантаження сторінки) не стирає чернетку.

Кнопка «Мій прогрес» у шапці відкриває дашборд: скільки розв'язано, скільки днів ви заходили, де зупинилися минулого разу (з кнопкою «Продовжити»), які конструкції вже освоєні, у яких темах найбільше невдалих спроб — із кнопкою «потренувати», що веде просто до потрібного завдання, — і п'ять завдань, які варто повторити. Тема вважається освоєною, лише коли розв'язані всі її завдання рівня, тож відмітки з'являються не одразу. Усе рахується з локальної історії, без мережі; історію можна очистити, не чіпаючи прогресу.

Наприкінці рівня екран «Ви тепер вмієте» перелічує здобуті вміння — відмітка стоїть лише там, де тема закрита повністю.

## Дані

Завдання спираються на девʼять таблиць. П'ять основних — `employees`, `customers`, `orders`,
`products`, `order_items` — живуть у [src/tasks/fixtures.js](src/tasks/fixtures.js) і підібрані
так, щоб працювали навчальні сценарії: є співробітник без департаменту (`IS NULL`), клієнт без
замовлень (`LEFT JOIN`), товари, яких ніхто не купував (anti-join), і посилання
`orders.manager_id` на продавця (self-join та звіти по менеджерах). До них додається
`raw_contacts` (рівень 6) — неочищені контакти з зайвими пробілами й регістром для рядкових
функцій.

Ще три таблиці — `app_users`, `app_events`, `app_purchases` (рівень 8, аналітичні кейси) —
живуть у [src/tasks/analyticsFixtures.js](src/tasks/analyticsFixtures.js) і, на відміну від
решти, не підібрані вручну: дані породжує `generate_series` разом із `md5` як джерелом
псевдовипадковості.

Колонки `hire_date` і `order_date` мають справжній тип `DATE`, а не текст, — тому з ними працює арифметика дат і `EXTRACT`.

## Запуск локально

```bash
npm install
npm run dev
```

Vite надрукує адресу, на якій підняв сервер, — зазвичай `http://localhost:5173`, але якщо порт
зайнятий, він мовчки візьме наступний вільний. Тому адресу варто брати з його виводу.

## Інші команди

```bash
npm test          # перевірки: завдання, звірка результатів, стан гри, UI
npm run lint      # ESLint
npm run format    # Prettier переписує файли (format:check — лише перевіряє)
npm run build     # продакшн-збірка у dist/
npm run preview   # перегляд зібраної версії
```

## Як додати завдання

Завдання лежать у `src/tasks/level1.js` … `level8.js`. Скопіюйте об'єкт-сусід і замініть поля. Обов'язкові: `id`, `level`, `tier` (`basic` / `medium` / `complex`), `title`, `context`, `schemaDescription`, `setupSql`, `taskText`, `expectedOutputColumns`, `referenceSql`, три `hints` і `explanation`.

Описи схем беріть з [src/tasks/schemas.js](src/tasks/schemas.js), а не пишіть рядком — тоді зміна колонки в даних не потребуватиме правок у десятках завдань.

Після додавання запустіть `npm test`. Перевіряється, що еталонний запит виконується проти `setupSql`, повертає хоча б один рядок, а назви його колонок точно збігаються з `expectedOutputColumns`. Окремо звіряється, що склад рівня відповідає `LEVEL_PLAN`, що складність усередині рівня не спадає, і що кожна таблиця, згадана в `referenceSql`, справді описана в `schemaDescription`.

Запити пишіть діалектом PostgreSQL: `DATE_TRUNC`, `EXTRACT`, `TO_CHAR` доступні, а `strftime` чи `julianday` із SQLite — ні. Тести виконують кожен еталонний запит справжнім Postgres, тож помилка діалекту не пройде непоміченою.
